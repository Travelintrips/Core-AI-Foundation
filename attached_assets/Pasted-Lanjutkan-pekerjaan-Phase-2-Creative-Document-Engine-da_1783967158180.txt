## 4. Selesaikan `pdf_export` worker

Pastikan `executeJob()` tidak lagi selalu melempar `WorkerNotImplementedError` untuk semua `pdf_export`.

Dispatch harus dibatasi berdasarkan service atau document type.

Contoh perilaku:

```ts
if (job.type === "pdf_export") {
  if (documentType === "company_profile") {
    return executeCompanyProfilePdfExportJob(job);
  }

  throw new WorkerNotImplementedError(
    `PDF export is not implemented for document type: ${documentType}`
  );
}
```

Jangan membuat seluruh jenis PDF memakai Company Profile mapper.

Worker Company Profile harus:

1. Memvalidasi payload.
2. Memuat project.
3. Memuat service request.
4. Memuat brief dan structured AI output.
5. Memuat asset gambar yang relevan.
6. Membentuk `CreativeDocumentSpec`.
7. Merender PDF.
8. Memvalidasi PDF.
9. Meng-upload ke storage.
10. Membuat atau memperbarui asset record.
11. Memastikan object storage benar-benar tersedia.
12. Return hasil terstruktur yang lulus `validateJobCompletion()`.
13. Baru mengizinkan dispatcher menandai job completed.

## 5. Completion guard compatibility

Periksa contract hasil worker dengan `jobCompletionGuard.ts`.

Pastikan return value memiliki seluruh field yang diminta oleh completion guard, misalnya:

* asset ID
* storage path
* file size
* MIME type
* project ownership
* final deliverable marker

Jangan melewati completion guard dan jangan menambahkan special-case yang melemahkan validasi.

Tambahkan requirement `application/pdf` untuk `pdf_export` jika belum ada.

## 6. Idempotency dan retry

Pastikan retry aman.

Gunakan identitas stabil berdasarkan:

* job ID
* project ID
* document type
* version

Perilaku:

* asset valid dan storage object ada → reuse
* asset ada tetapi storage object hilang → regenerate
* render selesai tetapi upload gagal → jangan buat asset final
* upload berhasil tetapi DB insert gagal → cleanup atau recovery yang aman
* retry tidak membuat banyak final asset untuk versi yang sama
* revision sah membuat versi baru

Tambahkan unique lookup atau deterministic storage path bila sesuai dengan schema saat ini.

## 8. PDF validation

Validator wajib memeriksa:

* buffer tersedia
* magic bytes `%PDF-`
* file size lebih dari nol
* MIME type `application/pdf`
* page count valid
* minimal tiga halaman untuk fixture standar
* bukan placeholder
* metadata title tersedia

Jika page count parser sudah ditambahkan, pastikan dependency:

* terinstall pada package yang benar
* masuk lockfile
* kompatibel dengan build
* tidak diimport di frontend

## 9. Storage dan asset record

Gunakan storage service existing.

Path final:

```text
creative-projects/{ownerId}/{projectId}/{jobId}/documents/company-profile-v{version}.pdf
```

Pastikan nama dan path disanitasi.

Asset metadata minimal:

* project ID
* request ID
* job ID
* owner ID
* asset type document
* document type company_profile
* filename
* MIME type
* storage path
* file size
* checksum
* page count
* version
* final deliverable true
* temporary preview false
* validation status
* generated timestamp

Jangan menyimpan signed URL sebagai URL permanen apabila sistem menggunakan token dinamis.

## 10. Workflow propagation

Pastikan workflow Company Profile benar-benar memasukkan `pdf_export` sebagai required final step.

Project tidak boleh completed hanya karena text atau image generation selesai.

Project completed hanya setelah:

* required content tersedia
* required images sesuai workflow tersedia
* PDF asset valid
* storage object ada
* completion guard lulus

Jika workflow sebelumnya belum meng-enqueue `pdf_export`, selesaikan integrasinya.

Pastikan enqueue tidak terjadi berulang setiap kali status project dibaca.

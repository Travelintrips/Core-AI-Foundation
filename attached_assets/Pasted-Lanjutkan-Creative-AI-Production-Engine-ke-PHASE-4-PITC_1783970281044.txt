# 3. Presentation Engine generik

Bangun Presentation Engine terpisah dari Document Engine.

Struktur yang disarankan:

```text
services/presentation/
├── creativePresentationRegistry.ts
├── creativePresentationWorkerService.ts
├── presentationTypes.ts
├── presentationValidationService.ts
├── presentationStorageService.ts
├── presentationAssetResolver.ts
├── presentationOverflowService.ts
├── presentationThumbnailService.ts
├── presentationPdfPreviewService.ts
├── presentationThemeService.ts
└── mappers/
    └── pitchDeckPresentationMapper.ts
```

Nama boleh disesuaikan dengan repository.

Jangan mencampurkan logic PPTX ke `creativeDocumentRegistry.ts`.

Gunakan registry tersendiri:

```ts
type CreativePresentationType =
  | "pitch_deck";
```

Contoh definition:

```ts
type PresentationDefinition = {
  presentationType: CreativePresentationType;
  serviceCodes: string[];
  filenamePrefix: string;
  minimumSlideCount: number;
  maximumSlideCount: number;
  requiresPdfPreview: boolean;
  requiresImages: boolean;
  mapper: PresentationMapper;
  contentGenerator?: PresentationContentGenerator;
  validateInput: PresentationInputValidator;
};
```

# 8. Text overflow protection

Text overflow adalah acceptance criterion kritis.

Buat helper seperti:

```ts
fitTextToBox()
truncateWithReport()
splitContentAcrossSlides()
```

Aturan:

* jangan biarkan text keluar dari slide
* jangan gunakan font terlalu kecil hanya agar semua teks muat
* minimum body font yang masuk akal
* split menjadi continuation slide jika diperlukan
* catat slide split dalam generation report
* bullet count dibatasi
* paragraph panjang diringkas atau dipisah
* title panjang harus ditangani

Testing harus memeriksa overflow secara deterministik sejauh memungkinkan.

# 13. PPTX validation service

Buat validator, misalnya:

```ts
validateGeneratedPresentation()
```

Validasi:

1. ZIP signature valid.
2. Required PPTX XML entries tersedia.
3. Slide count sama dengan spec.
4. Slide count memenuhi minimum.
5. File size lebih dari nol.
6. Metadata title tersedia.
7. Tidak ada duplicate slide relationship yang rusak.
8. Tidak ada placeholder marker.
9. Tidak ada string `undefined`, `null`, atau `[object Object]` dalam text XML.
10. Tidak ada asset dari project lain.

Jika menggunakan ZIP parser tambahan, pilih dependency ringan dan stabil.

# 16. Worker

Buat presentation worker nyata, misalnya:

```text
executePitchDeckPresentationExportJob()
```

Atau worker generik berdasarkan registry.

Flow:

1. Load job.
2. Resolve presentation type.
3. Load project/request/brief/output.
4. Validate ownership.
5. Resolve existing valid assets.
6. Resolve entitlement.
7. Normalize/generate slide content.
8. Map to `CreativePresentationSpec`.
9. Resolve visual assets.
10. Render PPTX.
11. Validate PPTX.
12. Upload PPTX.
13. Verify upload.
14. Create/update asset record.
15. Generate PDF preview jika required/supported.
16. Generate thumbnail.
17. Validate outputs.
18. Record generation report.
19. Return completion result.
20. Let completion guard finish job.

Untuk service selain Pitch Deck:

* tetap unsupported
* jangan fallback ke Pitch Deck mapper

# 22. Idempotency

Pertahankan pola shared document worker.

Perilaku:

* valid PPTX asset + object exists → reuse
* PPTX record ada, object hilang → regenerate same version
* PDF preview hilang tetapi PPTX valid → regenerate preview saja
* thumbnail hilang → regenerate thumbnail saja
* failed upload → no completed asset
* retry → no duplicate final asset
* approved revision → next version
* active export job → jangan enqueue duplicate

Gunakan deterministic keys.

MASTER AUDIT — END-TO-END CREATIVE AI ORDER FLOW
ORDER → BRIEF → WORKFLOW → PRODUCTION → DELIVERABLE → INVOICE → PAYMENT → CUSTOMER DELIVERY

TUJUAN

Lakukan audit end-to-end terhadap seluruh alur pemesanan Creative AI, khususnya
layanan Interior Design.

Masalah nyata yang harus direproduksi:

1. Customer membuat pesanan Interior Design.
2. Pesanan langsung masuk ke tahap hasil produksi.
3. Halaman hasil produksi dapat dibuka, tetapi isinya kosong.
4. Customer melihat status "Menunggu Pelunasan".
5. Halaman customer menyatakan:
   - proyek selesai;
   - file final terkunci;
   - file akan dibuka setelah pelunasan.
6. Namun pada Admin Panel:
   - data pembayaran kosong;
   - invoice/tagihan tidak terbentuk atau tidak terlihat;
   - hasil produksi/deliverable juga kosong.

Audit harus menemukan root cause pasti, memperbaiki alurnya, dan menambahkan
regression test.

Jangan hanya memperbaiki tampilan.

==================================================
ATURAN WAJIB
==================================================

1. Mulai dengan audit read-only.
2. Jangan langsung mengubah status database.
3. Jangan membuat data dummy sebagai solusi produksi.
4. Jangan hard-code khusus Interior Design jika penyebabnya ada di workflow
   universal.
5. Gunakan source of truth existing.
6. Jangan membuat tabel atau status tandingan tanpa kebutuhan yang terbukti.
7. Jangan menganggap project selesai hanya karena workflow step terakhir aktif.
8. Jangan menganggap pembayaran diperlukan jika invoice belum terbentuk.
9. Jangan menampilkan file terkunci jika file final sebenarnya belum ada.
10. Semua perubahan harus backward-compatible dan tenant-safe.

PHASE 5 — AUDIT WORKFLOW AND JOB EXECUTION
==================================================

Trace seluruh job untuk order yang direproduksi.

Periksa:

- job dibuat atau tidak;
- queue worker mengambil job atau tidak;
- agent/provider/model ter-resolve;
- input tersedia;
- output tervalidasi;
- output tersimpan;
- error tersimpan;
- retry terjadi;
- job selesai secara valid.

Cari kondisi berbahaya:

- missing output tetap ditandai success;
- `{}` dianggap output valid;
- `null` dianggap complete;
- exception ditelan;
- timeout dianggap success;
- skipped job dianggap successful;
- no renderer dianggap completed;
- worker tidak aktif tetapi step tetap maju;
- job status dan workflow status tidak sinkron.

Aturan yang harus diberlakukan:

A production step hanya boleh `completed` jika:

- job sukses;
- output contract valid;
- required output fields tersedia;
- artifact/deliverable persistence sukses;
- tidak ada unresolved blocking error.

- pembayaran tersimpan di table lain;

- admin route memakai order ID;
- invoice generator tidak dipanggil ketika final production selesai;
- final invoice bergantung pada event yang tidak pernah emitted;

Aturan wajib:

`awaiting_payment` hanya boleh aktif jika:

- invoice exists;
- invoice total > 0;
- outstanding amount > 0;
- payment destination tersedia;
- invoice/customer/order relation valid.

Jika invoice belum terbentuk:

- status harus `billing_pending` atau equivalent;
- customer tidak boleh diminta transfer berdasarkan data kosong.

PHASE 10 — EVENT AND STATUS TRANSITION AUDIT
==================================================

Cari semua event atau function yang dapat mengubah status:

- order completed;
- workflow completed;
- production completed;
- final files ready;
- invoice generated;
- payment required;
- payment verified;
- files unlocked.

Buat state transition table:

From | Event | Preconditions | To | Side effects | Rollback behavior

Required guards:

A. Workflow completed:
- all required stages completed;
- no failed blocking stage;
- all mandatory output contracts valid.

B. Production completed:
- minimum required artifacts persisted.

C. Final ready:
- final deliverables exist and storage objects are accessible.

D. Awaiting payment:
- valid invoice and outstanding balance exist.

E. Paid:
- verified payment total >= amount due.

F. Delivered:
- paid;
- final deliverables accessible;
- customer access grant active.

G. Completed:
- delivered or explicitly accepted;
- no unresolved blocking state.

Tidak boleh ada direct transition:

order_created → production_completed

atau:

production_completed → awaiting_payment

tanpa validasi artifact dan invoice.

==================================================
PHASE 13 — RECOVERY FOR EXISTING BROKEN ORDERS
==================================================

Buat recovery tool atau idempotent repair function untuk order yang sudah rusak.

Kategori recovery:

A. Project complete tetapi tidak ada job:
- reset ke production_pending;
- enqueue workflow secara idempotent.

B. Job sukses tetapi artifact belum tersimpan:
- re-persist dari validated job output jika tersedia.

C. Artifact ada tetapi deliverable belum dipublish:
- publish deliverable secara idempotent.

D. Deliverable ada tetapi invoice belum dibuat:
- generate invoice dari quotation/order canonical.

E. Status awaiting_payment tanpa invoice:
- ubah ke billing_pending;
- jangan meminta customer transfer.

F. Payment sudah ada tetapi tidak terkait:
- lakukan relink hanya jika match dapat dibuktikan;
- jangan menebak berdasarkan nominal saja.

Recovery harus:

- dry-run terlebih dahulu;
- tenant-scoped;
- idempotent;
- audit logged;
- tidak menghapus data;
- menghasilkan before/after report.

==================================================
KNOWN ROOT CAUSE 1 — DEF-001 TEST ISOLATION
==================================================

Masalah:

_submitDedup adalah module-level cache dan bertahan antar-test.

Akibat:

- test kedua dan ketiga dapat membaca data L1 cache dari test sebelumnya;
- DB mock tidak dipanggil seperti yang diharapkan;
- hasil test tidak independen.

Implementasikan test-only cache reset yang aman.

Contoh tujuan:

export function _testClearSubmitDedupCache(): void

atau nama setara yang konsisten dengan repository.

Rules:

- hanya untuk test;
- jangan diekspos melalui public API production;
- jangan mengubah runtime behavior;
- jangan menjadikan in-memory cache sebagai source of truth;
- DB-backed idempotency tetap primary guarantee.

Panggil reset tersebut pada beforeEach/afterEach targeted tests.

==================================================
KNOWN ROOT CAUSE 2 — DEF-001 INSERT COUNT ASSERTION
==================================================

Satu project creation yang berhasil melakukan sekitar tiga insert:

1. project;
2. review;
3. dashboard token/record.

Test sebelumnya salah mengharapkan:

db.insert dipanggil satu kali.

Perbaiki assertion agar memverifikasi hal yang benar.

Jangan hanya mengganti menjadi:

toHaveBeenCalledTimes(3)

tanpa memastikan insert mana yang project.

Lebih baik:

- inspeksi target table;
- identifikasi project insert;
- pastikan project insert hanya satu;
- pastikan duplicate request tidak membuat project insert kedua;
- pastikan review/dashboard record juga tidak terduplikasi secara tidak sah.

Gunakan table-aware atau payload-aware assertion.

==================================================
KNOWN ROOT CAUSE 3 — DEF-004 INTERNAL CLOSURE MOCKING
==================================================

Masalah:

listWorkspaceNotifications() memanggil listAllWorkspaceProjects()
melalui referensi internal module.

Mock exported function tidak mengganti referensi closure tersebut.

Akibat:

- test tidak menggunakan mocked project data;
- real DB path mengembalikan zero projects;
- notification result kosong.

Jangan mengubah production service hanya agar mock bekerja secara tidak wajar.

Gunakan salah satu pendekatan aman:

A. Ekstrak pure function:

buildWorkspaceNotificationsFromProjects(...)

atau nama canonical setara.

B. Dependency injection kecil pada internal helper jika repository sudah memakai pola tersebut.

Rekomendasi:

Ekstrak pure function yang menerima:

- projects;
- reviews;
- jobs/workflow data;
- current time jika diperlukan;
- tenant context.

Pure function mengembalikan WorkspaceNotification[].

Kemudian:

listWorkspaceNotifications()
tetap bertanggung jawab mengambil data dari DB,
lalu memanggil pure function tersebut.

Targeted test menguji pure function secara langsung,
tanpa DB mock yang rapuh.

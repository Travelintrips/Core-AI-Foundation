TEAM 03 — DYNAMIC BRIEF ENGINE

BRANCH WAJIB:
feature/team-03-dynamic-brief-engine

PERAN TEAM

Ubah fondasi Brief Wizard existing menjadi Dynamic Brief Engine yang dapat
merender dan memvalidasi brief berbeda berdasarkan project/service plugin.

PROJECT BRIEF

Creative AI sudah memiliki:

- Brief Wizard dengan beberapa langkah;
- service-specific brief configuration;
- field tambahan untuk Fashion, Interior, dan Company Profile;
- AI Guided Brief Assistant;
- planner pertanyaan;
- answer mapper;
- session storage;
- review dan completion summary.

Jangan membuang atau mengganti sistem tersebut. Bangun lapisan canonical schema
dan adapter agar brief dapat berkembang untuk semua project design.

Field tersebut harus berada dalam domain schema, bukan core schema.

TUJUAN

Bangun DynamicBriefEngine yang mendukung:

1. Universal core brief fields.
2. Domain-specific field sections.
3. Conditional visibility.
4. Required/optional rules.
5. Repeatable groups.
6. Typed options.
7. Validation rules.
8. Draft persistence.
9. Schema version.
10. Migration dari draft lama.
11. Derived completion progress.
12. Review-ready normalized output.
13. Human-readable summary.
14. Compatibility dengan AI Guided Brief Assistant.

Jangan membangun renderer UI besar jika berada di luar scope. Sediakan registry,
normalizer, validator, dan adapter yang dapat dipakai UI existing.

LEGACY COMPATIBILITY

- Existing brief records harus tetap terbaca.
- Existing wizard data tidak boleh hilang.
- Buat migration/normalization in-memory atau additive persisted version bila perlu.
- Unknown legacy field dipertahankan dalam extension bag jika aman.
- Jangan silent drop.

- membuat workflow engine;
- menghapus existing config.

ACCEPTANCE CRITERIA

1. Existing Fashion, Interior, dan Company Profile brief dapat dinormalisasi.
2. Schema dipilih berdasarkan service type/plugin.
3. Conditional fields bekerja deterministic.
4. Validation error memiliki field path dan user-facing message key.
5. Draft lama dapat dimigrasi tanpa kehilangan data.
6. Completion tidak sekadar menghitung semua field; gunakan required-visible fields.
7. Output normalized cocok untuk AI agent dan downstream engine.
8. Semua domain extension berada di namespace yang jelas.
9. Tidak ada hard-coded condition tersebar di banyak komponen.
10. Dokumentasikan cara plugin mendaftarkan schema brief.

AKUN ADMIN AWAL

Provision satu akun admin internal awal dengan email:

```text
abing2267@gmail.com
```

Ketentuan keamanan:

1. Jangan menulis password dalam source code frontend.
2. Jangan menyimpan password plaintext di database.
3. Jangan menaruh password di GitHub, log, seed terbuka, atau response API.
4. Ambil initial password dari environment variable:

```text
INITIAL_INTERNAL_ADMIN_PASSWORD
```

5. Password harus di-hash menggunakan mekanisme authentication yang sudah digunakan project.
6. Jika menggunakan Supabase Auth, buat user melalui admin/server-side API, bukan dari frontend.
7. Tambahkan profil internal:

```text
email: abing2267@gmail.com
role: owner
account_type: internal
status: active
must_change_password: true
```

8. Pada login pertama, user wajib mengganti password sebelum bisa menggunakan modul internal.
9. Jangan menampilkan nilai environment variable di log.
10. Seed harus idempotent: jika akun sudah ada, jangan membuat duplikat dan jangan mereset password tanpa perintah eksplisit.

Gunakan environment variable pada Replit Secrets:

```text
INITIAL_INTERNAL_ADMIN_EMAIL=abing2267@gmail.com
INITIAL_INTERNAL_ADMIN_PASSWORD=<diisi melalui Replit Secrets>
```

Jangan mengisi nilai password langsung ke file `.env.example`.

AUTHORIZATION BACKEND

Buat middleware atau gunakan middleware existing:

```ts
requireAuth
requireCustomer
requireInternalRole
requireRole
```

Contoh logika:

```ts
const INTERNAL_ROLES = [
  "owner",
  "admin",
  "manager",
  "internal_staff",
];
```

`requireInternalRole` harus:

1. memastikan user login;
2. membaca profil user dari database;
3. memastikan status user aktif;
4. memastikan account_type adalah internal;
5. memastikan role termasuk internal role;
6. mencatat akses sensitif ke audit log;
7. mengembalikan 401 jika belum login;
8. mengembalikan 403 jika role tidak sesuai.

Jangan percaya role yang dikirim dari client, localStorage, query parameter, atau request body.

Role harus dibaca dari session/auth token dan dikonfirmasi ke database.

SECURITY HARDENING

Audit dan pastikan:

* tidak ada admin password di source code;
* tidak ada role admin yang dapat diubah dari frontend;
* tidak ada endpoint internal tanpa middleware;
* tidak ada IDOR pada order, file, hasil AI, dan pekerjaan;
* customer hanya melihat datanya sendiri;
* file internal menggunakan signed URL;
* signed URL memiliki masa berlaku;
* download memverifikasi ownership atau internal permission;
* audit log mencatat user, aksi, resource, waktu, IP jika tersedia, dan hasil;
* login memiliki rate limiting;
* error login tidak membocorkan apakah email terdaftar;
* session cookie aman jika menggunakan cookie;
* CORS dibatasi;
* API key provider AI hanya tersedia di server;
* internal AI execution tidak dapat dipanggil customer melalui endpoint manual.

```text

```

```text

/logout
```

```text
must_change_password = false
```

TESTING WAJIB

1. Public catalog hanya mengembalikan Creative AI.

13. Seed admin tidak membuat user duplikat.

15. User dengan `must_change_password=true` dipaksa mengganti password.
16. Setelah mengganti password, user dapat masuk dashboard internal.
17. Build frontend customer berhasil.
18. Build frontend internal berhasil.
19. Typecheck backend berhasil.
20. Tidak ada secret yang ikut ter-commit.

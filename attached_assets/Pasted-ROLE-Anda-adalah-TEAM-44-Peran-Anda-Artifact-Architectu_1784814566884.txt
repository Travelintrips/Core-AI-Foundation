PHASE 6 — STORAGE PERSISTENCE
==================================================

Audit storage write.

Pastikan:

- upload benar-benar berhasil sebelum artifact marked stored;
- status tidak berubah stored hanya karena API call tidak melempar;
- object key deterministic dan tenant-scoped;
- retry upload idempotent;
- duplicate upload tidak menghasilkan konflik ambigu;
- partial upload dibersihkan atau ditandai failed;
- content length dicatat;
- content type dicatat;
- provider response divalidasi;
- storage error dipropagasikan;
- private bucket tetap private;
- tidak ada hard-coded public URL untuk private file.

Cari:

- DB record dibuat sebelum storage sukses tanpa compensation;
- storage sukses tetapi DB gagal dan menjadi orphan;
- DB sukses tetapi storage gagal;
- upload timeout dianggap success;
- presigned upload tidak pernah dikonfirmasi;
- object key collision lintas tenant.

Jika architecture mendukung transaksi terdistribusi terbatas:

- gunakan status `pending_storage`;
- konfirmasi storage;
- ubah menjadi `stored`;
- scanner mendeteksi orphan.

Jangan berpura-pura atomic antara DB dan object storage.

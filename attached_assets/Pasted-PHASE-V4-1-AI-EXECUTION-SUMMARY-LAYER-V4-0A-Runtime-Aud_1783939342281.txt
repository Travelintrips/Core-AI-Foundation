Sekarang fokus pada lapisan narasi publik agar customer memahami apa yang sedang dikerjakan oleh AI, mengapa hal tersebut penting, dan langkah berikutnya.

==================================================
TUJUAN
==================================================

Ubah pengalaman Workspace dari sekadar:

- step.started
- step.completed
- worker.started
- artifact.created

menjadi narasi customer-friendly seperti:

Creative Director AI selesai menganalisis brief Anda.

Hasil:
Tujuan utama proyek dan konteks bisnis telah diidentifikasi.

Mengapa penting:
Hasil ini menjadi dasar strategi dan arah eksekusi berikutnya.

Selanjutnya:
Brand Strategist AI akan menyusun positioning dan pesan utama.

==================================================
PRINSIP UTAMA
==================================================

Execution Summary bukan chain-of-thought.

Jangan pernah menampilkan:

- reasoning internal model;
- hidden prompt;
- system prompt;
- internal instruction;
- provider raw response;
- stack trace;
- API key;
- internal cost;
- internal scoring yang tidak tervalidasi;
- detail debugging;
- confidential metadata;
- raw generated output yang belum boleh dilihat customer.

Yang boleh ditampilkan:

- apa yang dimulai atau selesai;
- hasil publik tingkat tinggi;
- dampaknya terhadap project;
- tahap berikutnya;
- worker berikutnya;
- jumlah artifact jika nyata;
- status review;
- blocker customer-safe;
- waktu aktual;
- provider/model hanya jika memang diizinkan.

==================================================
LANGKAH 2 — SUMMARY MODEL
==================================================

Buat normalized customer-safe model, misalnya:

interface ExecutionSummary {
  eventId: string;
  eventType: CanonicalEventType;
  projectId: string;
  workerId: string | null;
  workerName: string | null;
  workerRole: string | null;
  title: string;
  summary: string;
  whyItMatters: string | null;
  nextStep: {
    title: string;
    workerRole: string | null;
    estimatedAt: string | null;
  } | null;
  status: "queued" | "working" | "completed" | "reviewing" | "failed" | "blocked";
  occurredAt: string;
  artifactCount: number | null;
  isCustomerActionRequired: boolean;
  customerAction: {
    label: string;
    route: string | null;
  } | null;
  sourceEventId: string;
  isDerived: boolean;
}

Jangan wajibkan field yang datanya tidak tersedia.

Gunakan null secara jujur.

LANGKAH 3 — DETERMINISTIC SUMMARY BUILDER
==================================================

Buat service pure dan testable, misalnya:

executionSummaryService.ts

Input:

- CanonicalEvent;
- workflow context;
- runtime worker metadata;
- next step;
- artifact/review summary;
- project state.

Output:

- ExecutionSummary.

Summary harus deterministik.

Jangan melakukan LLM call untuk menghasilkan summary pada fase ini.

Gunakan template customer-safe berdasarkan eventType dan metadata.

LANGKAH 4 — SUMMARY TEMPLATE LIBRARY
==================================================

Buat template per event.

Contoh:

project.workflow_started

Title:
“Your AI team has started working”

Summary:
“The project brief has been accepted and the production workflow has started.”

Why it matters:
“Your project is now moving from planning into active execution.”

Next:
Current first workflow step.

--------------------------------------------------

worker.assigned

Title:
“{Worker Role} joined the project”

Summary:
“{Worker Role} has been assigned to handle {Step Name}.”

Why it matters:
Gunakan teks berdasarkan role bila tersedia.

Next:
Step start atau current task.

--------------------------------------------------

step.started

Title:
“{Worker Role} started {Public Step Name}”

Summary:
“Work has started on {customer-safe step description}.”

Why it matters:
Jelaskan fungsi tahap tersebut secara singkat.

Next:
Null selama masih running, atau step berikutnya bila memang diketahui.

--------------------------------------------------

step.completed

Title:
“{Public Step Name} completed”

Summary:
“{Worker Role} completed this phase successfully.”

Why it matters:
Jelaskan hasil tingkat tinggi tanpa membuka reasoning atau output rahasia.

Next:
Workflow step berikutnya.

--------------------------------------------------

artifact.created

Title:
“New deliverable generated”

Summary:
“{Artifact Count} new output has been prepared for this project.”

Why it matters:
“The output will be reviewed before becoming available to you.”

Next:
Human review jika applicable.

--------------------------------------------------

review.requested

Title:
“Output entered quality review”

Summary:
“A reviewer is checking the output for quality, accuracy, and project alignment.”

Why it matters:
“This helps ensure the deliverable meets the approved brief.”

Next:
Review completion.

--------------------------------------------------

review.revision_requested

Title:
“Revision is in progress”

Summary:
“The reviewer requested adjustments before final delivery.”

Why it matters:
“The output is being refined to better match the approved brief.”

Next:
Relevant production step.

--------------------------------------------------

review.approved

Title:
“Output approved”

Summary:
“The deliverable passed quality review and is ready for the next stage.”

Next:
Customer review atau delivery.

--------------------------------------------------

step.failed

Title:
“An AI task needs attention”

Summary:
“The task could not be completed as expected and is being reviewed.”

Why it matters:
“The system is preventing an incomplete result from moving forward.”

Next:
Retry atau human intervention jika diketahui.

Jangan menampilkan internal technical error.

--------------------------------------------------

step.blocked

Title:
“Project step is temporarily blocked”

Summary:
“The next step is waiting for a required dependency or approval.”

Jika customer action diperlukan, tampilkan CTA nyata.

==================================================
LANGKAH 7 — NEXT STEP DERIVATION
==================================================

Next step harus berasal dari workflow context nyata.

Prioritas:

1. next pending workflow step;
2. waiting review state;
3. customer action;
4. delivery;
5. completed;
6. null.

Jangan hardcode urutan universal jika workflow berbeda per service.

Gunakan creative_project_steps ordering/configuration existing.

Tampilkan worker role berikutnya hanya jika dapat diturunkan secara valid.

==================================================
LANGKAH 8 — CUSTOMER ACTION REQUIRED
==================================================

Execution Summary harus bisa menandai tindakan customer nyata.

Contoh:

- review deliverable;
- approve output;
- request revision;
- submit payment proof;

Namun untuk fase ini, gunakan hanya action yang sudah ada pada runtime/project response.

Jangan menciptakan action baru.

CTA harus memakai route existing.

==================================================
LANGKAH 9 — API INTEGRATION
==================================================

Audit endpoint existing:

- project detail;
- events;
- SSE stream;
- activity feed.

Pilih pendekatan paling aman:

A. Tambahkan executionSummary ke CanonicalEvent secara additive melalui wrapper response;

atau

B. Tambahkan summaries array pada project detail/events response.

Disarankan:

{
  event: CanonicalEvent,
  summary: ExecutionSummary
}

Jangan mengubah CanonicalEvent model secara breaking.

SSE runtime.event dapat membawa:

{
  event: CanonicalEvent,
  summary: ExecutionSummary
}

Snapshot SSE juga dapat membawa summary.

Pertahankan backward compatibility untuk client yang hanya membaca event.

==================================================
LANGKAH 10 — SSE INTEGRATION
==================================================

SSE tetap hanya transport.

Pada saat canonical event dipublikasikan:

- derive ExecutionSummary server-side;
- kirim event + summary;
- cursor tetap berdasarkan canonical event;
- dedup tetap memakai eventId;
- summary tidak memengaruhi ordering;
- reconnect tidak menghasilkan summary berbeda untuk event yang sama.

Summary harus deterministik.

LANGKAH 15 — FAILURE SUMMARY
==================================================

“A task is being retried”

“The current step did not complete successfully and the system is preparing another attempt.”

Why it matters:
“No incomplete output will be sent for review.”

- provider name jika sensitif;
- stack trace;
- prompt;
- failed response body.

“A project specialist has been notified.”

Hanya bila notification/escalation benar-benar terjadi.

==================================================
LANGKAH 18 — PERFORMANCE
==================================================

Summary builder harus pure dan ringan.

Jangan query DB per event.

Fetch context secara batch.

Untuk project events:

- load workflow steps sekali;
- load worker metadata sekali;
- load artifact/review context sekali;
- derive semua summaries in memory.

Jangan membuat N+1.

SSE poller tidak boleh menambah query per event.

LANGKAH 19 — CACHING
==================================================

- bounded cache;
- invalidate jika source event/context berubah;
- jangan tambah distributed cache pada fase ini.

Jika tidak diperlukan, jangan buat cache.

PHASE 2 — CREATIVE AI SMART CHOICE BRIEF FORM
OBJECTIVE

Phase 1 UI Foundation sudah selesai.

Sekarang gunakan seluruh reusable component yang sudah tersedia di:

src/components/creative-ui/

untuk mengubah halaman brief Creative AI menjadi lebih user-friendly.

Prinsip utama:

User memilih opsi yang tersedia terlebih dahulu. Input teks hanya muncul jika user memilih “Lainnya” atau memang membutuhkan jawaban khusus.

Fokus fase ini adalah Smart Choice Form dan Progressive Disclosure.

Jangan mengimplementasikan AI Assistant, website scraping, AI autofill, atau recommendation API pada fase ini. Fitur tersebut akan dikerjakan pada fase berikutnya.

16. AUTOSAVE DAN DRAFT RESTORE

Autosave existing wajib tetap bekerja.

Tambahkan dukungan agar perubahan dari chips/cards ikut memicu autosave yang sama.

Ketentuan:

Jangan membuat sistem autosave kedua.
Jangan menambah interval baru jika sudah ada.
Gunakan state/form flow existing.
Jangan membuat request API untuk setiap hover atau search.
Autosave hanya saat value benar-benar berubah.
Hindari race condition.
Draft lama harus tetap bisa dipulihkan.
Custom Lainnya harus dipulihkan dengan benar.
Status “Saved just now” harus tetap valid.

Buat unit helper:

serializeMultiChoice()
parseMultiChoice()
normalizeLegacyValue()

Tempatkan di utility yang sesuai.

Tambahkan test untuk parser/serializer jika project sudah memiliki test framework.

19. PERFORMANCE

Jangan menggunakan React.memo, useMemo, atau useCallback secara membabi buta.

Gunakan hanya bila benar-benar mengurangi re-render.

Pastikan:

Search list tidak berat.
Daftar pilihan didefinisikan di luar component bila statis.
Mapping konfigurasi tidak dibuat ulang setiap render.
Tidak ada state ganda yang bisa berbeda antara chip dan field value.
Satu source of truth untuk setiap jawaban.
Tidak ada infinite autosave loop.

User dapat menyelesaikan sebagian besar brief dengan memilih chips/cards.

Required validation tetap bekerja.
Autosave tetap bekerja.
Draft lama tetap kompatibel.
Payload backend tidak berubah tipe atau kontraknya.
Semua layanan existing tetap dapat memakai brief.

Mobile responsive.
Build dan tests lolos.

Phase 7A-10B — Fix Supabase DEV Read-Only Connection

JANGAN deploy production.
JANGAN gunakan database production.
JANGAN mengubah data production.
JANGAN mengubah Repository Analyzer dulu.

MASALAH TERBUKTI:

SQLSTATE 25006
cannot execute INSERT in a read-only transaction

Terjadi pada:
- INSERT ai_coding_tasks
- worker registration
- worker lease update
- SELECT ... FOR UPDATE SKIP LOCKED ai_jobs
- audit log insert
- ai_schedules writes

Target:
Pulihkan runtime DEVELOPMENT agar menggunakan Supabase DEV PRIMARY WRITABLE connection.


==================================================
1. IDENTIFIKASI DATABASE YANG BENAR-BENAR DIPAKAI
==================================================

Audit seluruh source/config/env resolution untuk:

DATABASE_URL
DIRECT_URL
SUPABASE_URL
SUPABASE_DB_URL
POSTGRES_URL
PGHOST
PGPORT
PGDATABASE
PGUSER
PGSSLMODE

dan semua variable custom database lainnya.

Cari:
- artifacts/api-server
- lib/db
- root config
- workflow configuration
- development runtime configuration

Jangan tampilkan password/token penuh.

Laporkan:
variable mana yang benar-benar dipakai oleh API server
dan precedence/fallback-nya.


==================================================
2. IDENTIFIKASI ENDPOINT DATABASE
==================================================

Untuk connection runtime DEVELOPMENT, tampilkan secara aman:

host
port
database
username prefix/role tanpa credential
pooler/direct classification

Jangan tampilkan password.

Pastikan runtime tidak menggunakan:
- read replica
- read-only endpoint
- connection string production
- endpoint yang salah


==================================================
3. DATABASE SESSION DIAGNOSTIC
==================================================

Dari connection yang SAMA dengan API runtime jalankan:

SELECT current_database();

SELECT current_user;

SHOW transaction_read_only;

SHOW default_transaction_read_only;

SELECT pg_is_in_recovery();

SELECT inet_server_addr(), inet_server_port();

SELECT
  current_setting('transaction_read_only') AS transaction_read_only,
  current_setting('default_transaction_read_only') AS default_transaction_read_only;

Catat hasil aktual.


==================================================
4. BEDAKAN 3 KEMUNGKINAN
==================================================

Tentukan berdasarkan evidence apakah penyebabnya:

A. API terhubung ke read replica/read-only endpoint

B. role/session mempunyai:
   default_transaction_read_only = on

C. application code membuka transaction sebagai READ ONLY

Jangan menebak.


==================================================
5. AUDIT SOURCE TRANSACTION
==================================================

Cari seluruh source:

SET TRANSACTION READ ONLY
SET SESSION CHARACTERISTICS
default_transaction_read_only
transaction_read_only
BEGIN READ ONLY
readOnly
read_only

Pastikan wrapper transaction di lib/db tidak secara global membuat
transaction read-only.

Jika source menyebabkan read-only:
perbaiki source.

Jika connection/env salah:
perbaiki DEVELOPMENT configuration saja.


==================================================
6. WRITABILITY PROBE
==================================================

Setelah root cause diperbaiki, jangan langsung menjalankan analyzer.

Lakukan probe transaction yang aman pada DEV.

Gunakan tabel temporary jika PostgreSQL/Supabase mengizinkan:

BEGIN;

CREATE TEMP TABLE dev_write_probe (
  id integer
);

INSERT INTO dev_write_probe VALUES (1);

SELECT * FROM dev_write_probe;

ROLLBACK;

Expected:
semua berhasil.

Jika TEMP TABLE tidak dapat digunakan karena policy environment,
gunakan mekanisme DEV-only yang tidak meninggalkan data permanen.

Jangan melakukan probe pada production.

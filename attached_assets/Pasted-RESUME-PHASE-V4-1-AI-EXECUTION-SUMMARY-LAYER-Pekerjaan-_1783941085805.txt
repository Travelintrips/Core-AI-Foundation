LANGKAH 2 — VERIFY SUMMARY ARCHITECTURE
==================================================

Pastikan hanya ada satu execution summary layer.

- REST events response;

- activity feed;

Frontend hanya boleh merender atau menggunakan safe fallback bila summary tidak tersedia.

==================================================
LANGKAH 3 — VERIFY DETERMINISM
==================================================

Pastikan:

- same CanonicalEvent + same context menghasilkan summary yang sama;
- tidak ada Date.now(), Math.random(), hash-based fake values, atau LLM call;
- cursor tetap berdasarkan canonical event;
- summary tidak mengubah event ordering;
- reconnect menghasilkan summary yang sama;
- duplicate event tidak membuat duplicate summary.

Tambahkan test jika bagian ini belum tercakup.

==================================================
LANGKAH 8 — MANUAL VERIFICATION
==================================================

Cari test data dengan aman. Jangan mengubah data customer produksi.

Gunakan existing dev/seed project atau test fixture.

Verifikasi minimal:

A. Running project
- worker role nyata;
- task summary tampil;
- what happened jelas;
- no fake progress;
- next step berasal dari workflow;
- SSE updates without refresh bila event dapat dipicu dengan aman.

B. Completed step
- title dan summary jelas;
- why-it-matters tersedia;
- next worker/step benar.

C. Artifact generated
- artifact summary benar;
- CTA hanya muncul jika filesUnlocked/permission mengizinkan;
- locked artifact tidak dapat dibuka.

D. Human review
- review.requested/approved/revision summary customer-safe;
- no reviewer-internal data leak.

E. Failed or blocked step
- pesan aman;
- tidak ada raw error/provider failure detail;
- customer action hanya muncul jika nyata.

F. No-runtime project
- honest fallback;
- no fabricated summary;
- no fake current worker.

Verifikasi desktop 1440px dan mobile 390px.

Ambil screenshot bila tooling tersedia.

Jika live token tidak tersedia, gunakan safe dev fixture atau visual verification dengan mocked test route. Jangan memanipulasi token customer nyata.

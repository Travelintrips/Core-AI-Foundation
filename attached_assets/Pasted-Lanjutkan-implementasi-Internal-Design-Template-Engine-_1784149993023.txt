# 4. Pipeline Render

Implementasikan pipeline berikut:

```text
1. Ambil design_render_item
2. Verifikasi tenant_id
3. Ambil immutable template version
4. Validasi ulang template JSON
5. Validasi input data
6. Resolve variables dan formatter
7. Evaluate conditional visibility
8. Resolve seluruh asset yang diperlukan
9. Bangun SVG deterministic
10. Render melalui Sharp
11. Encode sesuai output format
12. Upload hasil
13. Update design_render_item
14. Sinkronkan progress batch
15. Catat warning dan metrik render
```

Setiap tahap harus menghasilkan structured error apabila gagal.

# 5. Status Render Item

Gunakan status lifecycle existing. Jika belum lengkap, gunakan status minimal berikut tanpa merusak Phase 1:

```text
queued
processing
completed
failed
cancelled
```

Ketika worker mulai:

* pastikan item masih dapat diproses,
* set status `processing`,
* increment attempt secara atomik,
* simpan `started_at`.

Ketika berhasil:

* set status `completed`,
* simpan output asset atau URL,
* simpan width, height, format, file size jika kolom tersedia,
* simpan `completed_at`,
* hapus error lama.

Ketika gagal:

* set status sesuai mekanisme retry existing,
* simpan error code yang stabil,
* simpan pesan error yang sudah disanitasi,
* jangan menyimpan stack trace sensitif pada field yang terlihat user.

Satu item gagal tidak boleh menggagalkan seluruh batch.

# 6. Idempotency dan Race Protection

Sebelum merender, cek apakah item yang sama sudah memiliki output valid.

Gunakan kombinasi:

* template version ID,
* normalized input hash,
* format,
* requested dimensions,
* renderer version.

Jika output valid sudah ada:

* jangan render ulang,
* gunakan kembali hasil existing,
* update job sebagai sukses secara idempotent.

Cegah dua worker memproses item yang sama secara bersamaan menggunakan pola atomic claim atau transaction yang sudah dipakai repository.

Jangan hanya mengandalkan pengecekan status biasa tanpa race protection.

Tambahkan `rendererVersion`, misalnya:

```text
design-svg-renderer-v1
```

ke dalam hash atau metadata supaya perubahan renderer dapat membedakan cache lama dan baru.

# 7. SVG Intermediate Renderer

Gunakan SVG sebagai intermediate format utama.

SVG root harus:

* memiliki width dan height eksplisit,
* memiliki `viewBox`,
* menggunakan koordinat canvas template,
* tidak mengandung script,
* tidak mengandung event handler,
* tidak mengandung arbitrary `foreignObject`,
* tidak memuat external entity,
* tidak mengambil resource remote langsung.

Contoh:

```xml
<svg
  xmlns="http://www.w3.org/2000/svg"
  width="1080"
  height="1350"
  viewBox="0 0 1080 1350"
>
  ...
</svg>
```

Escape seluruh text content sebelum dimasukkan ke XML.

Semua remote image harus di-resolve terlebih dahulu dan dimasukkan sebagai buffer/data URI yang sudah divalidasi atau referensi internal yang aman.

# 9. Text Overflow Engine

Implementasikan urutan overflow berikut:

```text
1. Normalize text
2. Wrap berdasarkan lebar text box
3. Hitung jumlah baris
4. Jika terlalu besar, kurangi font size bertahap
5. Berhenti pada minimumFontSize
6. Jika masih overflow, truncate
7. Tambahkan ellipsis jika diizinkan
8. Catat warning
```

Jangan hanya memperkirakan jumlah karakter berdasarkan `text.length`.

Gunakan pengukuran teks yang tersedia dari Sharp/Pango atau utility yang stabil.

Jika pengukuran exact sulit dilakukan dalam environment:

* buat estimator yang teruji,
* gunakan font metrics,
* tambahkan safety margin,
* benchmark dengan font yang didaftarkan.

Preview dan final render wajib menggunakan text-layout logic yang sama.

Tambahkan warning seperti:

```text
TEXT_AUTO_SHRINK_APPLIED
TEXT_TRUNCATED
UNSUPPORTED_FONT_FALLBACK
MAX_LINES_EXCEEDED
```

# 13. Output Format

Dukung:

```text
png
jpg / jpeg
webp

```

## PNG

* preserve transparency,
* valid dimensions,
* output valid.

## JPG

* flatten transparency dengan background yang ditentukan,
* gunakan kualitas default aman,
* validasi rentang kualitas.

## WebP

* gunakan kualitas default aman,
* dukung transparency.

## PDF

Jangan membuat PDF yang hanya berisi buffer rusak atau ekstensi palsu.

### Pilihan A

### Pilihan B

Gunakan SVG-to-PDF hanya jika library existing stabil.

Untuk Phase 2, pilihan A lebih aman dan konsisten.

Ukuran halaman PDF harus mengikuti rasio dan ukuran template.

Catat dalam metadata bahwa PDF menggunakan rasterized canvas jika memang demikian.

# 16. Implementasi executeDesignRenderJob()

Ganti stub `executeDesignRenderJob()` dengan implementasi produksi.

Payload job minimal harus membawa identifier, bukan seluruh template dan gambar besar:

```ts
{
  tenantId: string;
  renderItemId: string;
  batchId?: string;
  requestId?: string;
}
```

Worker harus membaca data canonical dari database.

Jangan menjadikan job payload sebagai source of truth.

Flow:

```text
claim render item
    ↓
load immutable template version
    ↓
validate tenant and status
    ↓
render
    ↓
upload
    ↓
complete item
    ↓
sync batch counters
```

Gunakan transaction executor jika repository sudah memiliki contract tersebut.

Pastikan worker tidak jatuh ke plain DB client ketika sedang berada dalam transaction.

# 17. Batch Progress Synchronization

Setelah setiap item:

* update status item,
* sinkronkan batch counter,
* tentukan status batch yang sebenarnya.

Aturan:

```text
semua selesai tanpa gagal → completed
selesai dengan sebagian gagal → partially_failed
semua terminal dan semuanya gagal → failed
masih ada queued/processing → processing
batch dibatalkan → cancelled sesuai lifecycle existing
```

Gunakan query aggregate canonical atau counter update yang race-safe.

Jangan menghasilkan progress di atas 100%.

Jangan mengandalkan counter yang bisa drift tanpa reconciliation.

Tambahkan fungsi reconciliation apabila counter batch tidak cocok dengan item aktual.

# 18. Cancellation

Sebelum tahap mahal:

* cek apakah batch atau item sudah dibatalkan.

Periksa setidaknya:

* sebelum resolve asset besar,
* sebelum Sharp render,
* sebelum upload.

Jika cancellation terjadi saat Sharp sedang memproses, worker dapat menyelesaikan operasi aktif tetapi tidak boleh menyimpan hasil sebagai completed jika lifecycle menyatakan cancelled.

Dokumentasikan bahwa cancellation bersifat cooperative.

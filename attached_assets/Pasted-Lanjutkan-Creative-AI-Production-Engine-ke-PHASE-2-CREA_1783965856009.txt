## 2. Bangun Creative Document Engine generik

Buat service generik, misalnya:

`creativeDocumentService.ts`

Gunakan nama lain hanya jika lebih sesuai dengan struktur repository.

Engine harus menerima document specification terstruktur, bukan HTML mentah yang tidak terkontrol.

Contoh contract:

```ts
type CreativeDocumentSpec = {
  documentType: string;
  title: string;
  subtitle?: string;
  company?: {
    name?: string;
    logoUrl?: string;
    website?: string;
    email?: string;
    phone?: string;
    address?: string;
  };
  theme?: {
    primaryColor?: string;
    secondaryColor?: string;
    accentColor?: string;
    fontFamily?: string;
  };
  cover?: {
    title: string;
    subtitle?: string;
    imageUrl?: string;
    tagline?: string;
  };
  sections: CreativeDocumentSection[];
  footer?: {
    text?: string;
    showPageNumber?: boolean;
  };
  metadata?: Record<string, unknown>;
};
```

Section minimal mendukung:

```ts
type CreativeDocumentSection =
  | {
      type: "heading";
      title: string;
      subtitle?: string;
    }
  | {
      type: "paragraph";
      text: string;
    }
  | {
      type: "bullets";
      items: string[];
    }
  | {
      type: "image";
      imageUrl: string;
      caption?: string;
      alt?: string;
    }
  | {
      type: "keyMetrics";
      items: Array<{
        label: string;
        value: string;
      }>;
    }
  | {
      type: "table";
      headers: string[];
      rows: string[][];
    }
  | {
      type: "quote";
      text: string;
      attribution?: string;
    }
  | {
      type: "pageBreak";
    };
```

Buat schema validation menggunakan library validation yang sudah tersedia di repository.

Input invalid harus gagal dengan error terstruktur dan tidak menghasilkan PDF setengah jadi.

## 3. Rendering PDF

Gunakan `pdfkit` yang sudah tersedia.

PDF harus benar-benar memiliki layout profesional, minimal:

* ukuran A4 portrait
* margin konsisten
* cover page
* judul dan subjudul
* warna brand
* section heading
* paragraph wrapping
* bullet lists
* image placement
* image caption
* table sederhana
* key metrics cards atau blocks
* footer
* nomor halaman
* automatic page break
* closing page

Jangan hanya:

* menulis JSON mentah
* menempel seluruh teks dalam satu halaman
* membuat PDF berupa screenshot tunggal

Buat layout helper agar fungsi renderer tidak menjadi satu file monolitik.

Contoh helper:

* `renderCoverPage()`
* `renderSectionHeading()`
* `renderParagraph()`
* `renderBullets()`
* `renderImageBlock()`

* `ensurePageSpace()`

Gunakan nama sesuai style repository.

## 7. PDF worker nyata

Ganti perilaku `pdf_export` khusus Company Profile menjadi worker nyata.

Alur:

1. Load job payload.
2. Validasi job type dan project ownership.
3. Load project, service request, brief, dan output AI.
4. Build Company Profile document spec.
5. Render PDF ke temporary buffer atau temporary file.
6. Validasi PDF.
7. Upload ke Supabase Storage.
8. Buat atau update `creative_ai_assets`.
9. Return structured result yang memenuhi completion guard.
10. Baru izinkan dispatcher memanggil `completeJob()`.

Jangan menonaktifkan completion guard.

Untuk jenis PDF lain yang belum diimplementasikan:

* tetap throw `WorkerNotImplementedError`
* jangan mencoba merender generic output yang belum memiliki mapper

Gunakan dispatch berdasarkan document type atau service slug.

## 8. Validasi PDF sebelum upload

Tambahkan validator, misalnya:

`validateGeneratedPdf()`

Validasi minimal:

* buffer tersedia
* file size lebih dari nol
* magic bytes dimulai dengan `%PDF-`
* MIME type `application/pdf`
* page count dapat dibaca jika library tersedia
* minimal 3 halaman untuk fixture standar Company Profile
* tidak hanya berisi halaman kosong
* judul atau metadata document tersedia
* output bukan placeholder

Jangan hanya mempercayai ekstensi `.pdf`.

Jika page count membutuhkan dependency baru, pilih dependency ringan dan stabil. Jangan menambahkan library besar tanpa alasan.

## 9. Storage path

Gunakan struktur path yang konsisten:

```text
creative-projects/{companyId}/{projectId}/{jobId}/documents/company-profile-{version}.pdf
```

Jika `companyId` tidak tersedia, gunakan tenant atau owner identifier yang memang digunakan codebase.

Hindari:

* nama file dari input customer tanpa sanitasi
* path traversal
* bucket public untuk final deliverable
* URL permanen yang melewati payment gate

Final deliverable tetap menggunakan signed access mechanism yang ada.

## 11. Idempotency

Retry job tidak boleh menghasilkan asset duplikat tidak terkendali.

Gunakan key idempotency berdasarkan:

* job ID
* project ID
* document type
* version atau attempt yang sah

Perilaku retry:

* jika file valid dan asset record sudah lengkap, return existing valid deliverable
* jika asset record ada tetapi storage file hilang, regenerate dan repair record
* jika upload gagal, jangan membuat asset final palsu
* jika render gagal, temporary file harus dibersihkan
* jangan membuat project completed dua kali

## 12. Versioning

Company Profile harus mendukung minimal version metadata.

Versi pertama:

```text
v1
```

Pada regenerate atau revision yang sah:

```text
v2
v3
```

Jangan overwrite file lama tanpa audit trail.

Customer workspace untuk fase ini cukup menampilkan versi terbaru, tetapi struktur backend jangan menghalangi future version history.

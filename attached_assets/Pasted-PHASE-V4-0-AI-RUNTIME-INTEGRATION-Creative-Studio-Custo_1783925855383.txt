==================================================
LANGKAH 4 — GAP ANALYSIS
==================================================

Kelompokkan gap menjadi:

CRITICAL
- project customer tidak membuat job
- job tidak memiliki project_id/request_id
- worker tidak menulis event
- output tidak disimpan
- authorization tenant tidak aman
- status frontend tidak dapat dipercaya

HIGH
- progress tidak tersedia
- queue position tidak tersedia
- retry tidak terlihat
- failure state tidak masuk workspace
- artifacts tidak terhubung ke job
- provider/model metadata tidak tercatat

MEDIUM
- ETA belum tersedia
- cost/token usage belum tampil
- event naming tidak konsisten
- polling terlalu berat
- event retention belum jelas

LOW
- naming
- formatting
- animation
- icon
- non-critical metadata

==================================================
ACCEPTANCE CRITERIA AKHIR
==================================================

V4.0 dianggap selesai hanya jika:

- production project membuat AI job nyata
- job terhubung ke customer project
- dispatcher menugaskan worker nyata
- worker menghasilkan runtime event nyata
- progress tidak random
- Workspace membaca runtime snapshot
- Workspace menerima update realtime atau polling fallback
- artifacts terhubung ke job
- review state terhubung ke runtime
- failure dan retry terlihat aman
- customer tidak dapat melihat project lain
- tidak ada Demo Preview pada data yang sudah live
- typecheck, build, test, dan security test lulus

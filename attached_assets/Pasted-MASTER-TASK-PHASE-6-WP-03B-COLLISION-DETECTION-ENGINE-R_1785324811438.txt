========================================================
PHASE 4 — AABB BROAD PHASE
========================================================

Implement AABB broad-phase collision checks.

Requirements:

- fast rejection before SAT
- touching edges are configurable
- deterministic results
- no false negatives before narrow phase
- supports rotated furniture through world-space AABB generation
- handles zero or invalid dimensions safely
- does not mutate placement objects

Expose a pure function similar to:

checkAabbOverlap(a, b, options)

Do not treat AABB overlap alone as a confirmed collision for
rotated objects.

========================================================
PHASE 5 — OBB / SAT NARROW PHASE
========================================================

Implement OBB collision detection using the Separating Axis
Theorem.

Requirements:

- axes derived from both rectangles
- projection of all corners
- overlap depth where available
- touching behavior configurable
- correct handling of rotations including:
  0, 45, 90, 135, 180, 270, and 360 degrees
- deterministic collision pair ordering
- no false positive from AABB-only overlap

Expose a pure function similar to:

checkObbCollision(a, b, options)

Return structured results, not only a boolean.

Suggested result fields:

- collides
- touching
- penetrationDepth
- separatingAxis
- pair
- reason

========================================================
PHASE 6 — ROOM BOUNDARY VALIDATION
========================================================

Validate furniture placement against room boundaries.

Support:

- rectangular room boundaries
- polygon room boundaries if already represented in the design
- fully inside
- partially outside
- fully outside
- wall penetration
- boundary touching
- rotation near corners

Return structured violations.

Do not automatically move or correct furniture.

Validation only.

========================================================
PHASE 7 — CLEARANCE ZONES
========================================================

Implement clearance zones as soft validation warnings.

Support clearance around:

- furniture item
- front access side
- rear side
- left side
- right side
- all sides

Requirements:

- clearance is not a hard collision by default
- severity configurable
- actual furniture overlap remains a hard error
- clearance overlap returns warnings
- clearance zones rotate with furniture where required
- no persistence redesign

Do not implement walkway planning beyond basic clearance-zone
validation.

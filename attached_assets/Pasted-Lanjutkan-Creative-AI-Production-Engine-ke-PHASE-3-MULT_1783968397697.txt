# 10. Shared worker contract

Buat konfigurasi document type, misalnya:

```ts
type DocumentDefinition = {
  documentType: CreativeDocumentType;
  serviceSlugs: string[];
  filenamePrefix: string;
  minimumPageCount: number;
  requiresImages: boolean;
  requiresLogo: boolean;
  mapper: DocumentMapper;
  contentGenerator?: DocumentContentGenerator;
  validateInput: DocumentInputValidator;
};
```

Gunakan registry agar worker tidak penuh dengan banyak `if/else`.

Contoh:

```ts
const DOCUMENT_DEFINITIONS = {
  company_profile: { ... },
  brand_strategy: { ... },
  copywriting: { ... },
  creative_consultation: { ... },
  brand_identity_guideline: { ... },
};
```

Worker generic:

```text
resolve type
→ load definition
→ load project data
→ validate required inputs
→ resolve assets
→ generate/normalize content
→ map to document spec
→ render
→ validate
→ upload
→ verify
→ record asset
→ return completion result
```

# 11. Idempotency

Pertahankan perilaku Phase 2.

Untuk semua document type:

* valid asset + valid storage → reuse
* asset ada, storage hilang → regenerate same version
* render gagal → no final asset
* upload gagal → no completed asset
* verification gagal → failed
* fresh generation → version 1
* approved revision → next version
* retry tidak membuat duplicate final row

Asset uniqueness harus mempertimbangkan:

* project ID
* document type
* version
* final deliverable marker

Company Profile behavior tidak boleh berubah.

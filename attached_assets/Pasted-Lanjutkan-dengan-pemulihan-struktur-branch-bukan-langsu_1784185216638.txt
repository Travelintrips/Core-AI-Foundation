# BAGIAN 1 — AMANKAN KONDISI SAAT INI

Pastikan working tree bersih.

File prompt yang untracked bukan kode. Jangan commit file tersebut kecuali memang diminta.

Buat tag atau branch safety sebelum melakukan perubahan:

```bash
git branch safety/main-with-phase3b-352d4d6 352d4d6
```

Verifikasi:

```bash
git show --stat 352d4d6
git branch --contains 352d4d6
```

Jangan melakukan reset sebelum branch safety berhasil dibuat.

# BAGIAN 2 — BUAT BRANCH TEAM 2 DARI BASELINE PHASE 2

Buat branch Team 2 dari baseline resmi:

```bash
git switch -c feature/design-template-phase3b-zip 2a4dc6c
```

Cherry-pick submission Team 2:

```bash
git cherry-pick 352d4d6
```

Jika cherry-pick conflict:

1. baca perubahan secara semantik,
2. jangan memilih accept-all,
3. selesaikan hanya conflict yang terkait Phase 3B,
4. jalankan test Team 2,
5. lanjutkan cherry-pick.

Setelah berhasil:

```bash
git log --oneline --decorate -5
git diff 2a4dc6c..HEAD --stat
```

Branch Team 2 sekarang harus berisi perubahan ZIP export saja.

Catat commit SHA baru hasil cherry-pick. SHA kemungkinan berbeda dari `352d4d6`.

# BAGIAN 3 — KEMBALIKAN MAIN KE BASELINE YANG BENAR

Lakukan hanya setelah:

* safety branch tersedia,
* branch Team 2 tersedia,
* hasil cherry-pick terverifikasi.

Karena `main` lokal belum boleh memuat Phase 3B sebelum review, kembalikan `main` ke baseline Phase 2:

```bash
git switch main
git reset --hard 2a4dc6c
```

Jangan push force ke remote saat authentication belum tersedia.

Verifikasi:

```bash
git status
git log --oneline -5
```

Main lokal harus kembali ke:

```text
2a4dc6c
```

Branch safety dan branch Team 2 tetap menyimpan perubahan.

# BAGIAN 4 — JANGAN MENGONFIGURASI TOKEN SECARA SEMBARANGAN

Jangan meminta atau menulis token GitHub langsung di:

* source code,
* command history yang dicetak ke laporan,
* `.env` committed,
* file repository,
* chat output.

Token harus ditambahkan oleh pemilik repository melalui Replit Secrets atau integrasi GitHub resmi.

Nama secret mengikuti konfigurasi environment existing, misalnya:

```text
GITHUB_TOKEN
```

atau gunakan GitHub App/credential helper yang sudah didukung Replit.

Jangan mengarang nilai token.

Setelah credential tersedia, verifikasi tanpa menampilkan token:

```bash
git ls-remote origin
git fetch --all --prune
```

Laporkan hanya sukses/gagal.

# BAGIAN 5 — CARI APAKAH BRANCH TIM TERDAPAT DI WORKTREE ATAU REF LAIN

Sebelum menyimpulkan pekerjaan hilang, periksa:

```bash

git show-ref
git reflog --all --date=iso
git worktree list
git fsck --full --no-reflogs --unreachable
```


2. bandingkan terhadap baseline `2a4dc6c`,
3. pastikan scope cocok,
4. buat branch recovery,
5. laporkan sebelum review.

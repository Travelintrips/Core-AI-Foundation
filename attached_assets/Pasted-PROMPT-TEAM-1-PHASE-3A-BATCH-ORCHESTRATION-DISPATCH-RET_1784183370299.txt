Batch Lifecycle

Gunakan state machine eksplisit.

Status minimal:

draft
queued
dispatching
processing
completed
partially_failed
failed
cancelling
cancelled

Jangan memasukkan status ZIP ke lifecycle utama jika Team 2 menggunakan export record terpisah.

Valid transition:

draft → queued
queued → dispatching
dispatching → processing
processing → completed
processing → partially_failed
processing → failed
queued → cancelling
dispatching → cancelling
processing → cancelling
cancelling → cancelled
partially_failed → queued melalui retry
failed → queued melalui retry

Transition ilegal harus ditolak dengan structured error.

Buat helper:

assertBatchTransition(currentStatus, nextStatus)

Tambahkan unit test semua transition valid dan invalid.

Logical Deduplication

Pastikan duplicate dispatcher tidak menghasilkan duplicate logical render.

Gunakan state canonical seperti:

dispatch_status = pending
dispatch_status = dispatching
dispatch_status = dispatched

Jika enqueue berhasil tetapi proses mati sebelum update marker, re-delivery tetap aman karena worker Phase 2 idempotent. Namun dispatcher juga harus memperkecil duplicate enqueue.

Dokumentasikan failure window dan mitigation-nya.

Retry Policy

Gunakan error retryability Phase 2.

Konfigurasi:

DESIGN_RENDER_MAX_ATTEMPTS=3

Backoff minimal:

attempt 1 → immediate
attempt 2 → +30 detik
attempt 3 → +2 menit

Boleh mengikuti retry framework existing jika lebih konsisten.

Non-retryable error harus terminal.

Bedakan:

render attempt,

Manual retry endpoint harus:

tidak menyentuh completed item,

enqueue dispatcher.
Cancellation

Implementasikan:

queued|dispatching|processing → cancelling → cancelled

Saat cancel:

queued item menjadi cancelled,
item completed tetap completed,
item failed tetap dapat dipertahankan sebagai failed,
dispatcher berhenti,
worker aktif mendeteksi cooperative cancellation,
setelah tidak ada processing item, batch menjadi cancelled.

Endpoint cancel harus idempotent.

Jangan menghapus output completed.

==================================================
LANGKAH 2 — VERIFY RUNTIME ADAPTER
==================================================

Audit service/adapter runtime roster yang sudah dibuat.

Pastikan adapter:

- membaca creative_project_steps yang terkait dengan project customer;
- tidak membaca step project lain;
- menormalisasi status nyata;
- tidak membuat progress random;
- tidak membuat confidence palsu;
- menggunakan ai_agents / ai_employees / ai_departments hanya sebagai metadata enrichment;
- mempunyai safe fallback jika metadata tidak ditemukan;
- tidak mengekspos prompt, secret, raw provider response, stack trace, atau internal metadata sensitif.

Normalized worker response minimal:

- id
- roleKey
- displayName
- department
- specialty
- stepId
- stepName
- status
- currentTask
- provider
- model
- startedAt
- completedAt
- outputCount
- attempt
- isHuman
- source
- isLive

Field boleh optional jika source data tidak tersedia.

==================================================
LANGKAH 3 — VERIFY PROJECT LINKAGE
==================================================

Pastikan hubungan berikut benar:

workspace token
→ customer workspace/project
→ creative project/workflow
→ creative_project_steps

Periksa secara langsung:

- key/foreign key yang digunakan;
- query condition;
- tenant/company scoping;
- project ownership;
- behavior untuk project lama;
- behavior jika workflow belum dimulai;
- behavior jika step kosong.

Jangan hanya mengandalkan projectId dari client.

Semua ownership harus divalidasi server-side.

==================================================
LANGKAH 4 — VERIFY CURRENT TASK LOGIC
==================================================

Current task harus dipilih dengan urutan yang konsisten:

1. running / in_progress step;
2. waiting_review / reviewing step;
3. blocked / failed step bila perlu perhatian;
4. latest completed step;
5. next pending step;
6. null jika tidak ada runtime.

Pastikan current task berasal dari backend runtime snapshot, bukan stage-to-worker mapping frontend.

Response harus customer-safe.

==================================================
LANGKAH 5 — VERIFY WORKSPACE API
==================================================

Periksa endpoint workspace project detail yang telah diubah.

Pastikan response baru bersifat backward compatible.

Struktur yang diharapkan kurang lebih:

runtime: {
  source: "creative_workflow",
  isLive: boolean,
  workers: RuntimeWorkerSnapshot[],
  currentTask: RuntimeCurrentTask | null,
  currentWorkerId: string | null,
  currentStepId: string | null,
  lastUpdatedAt: string | null
}

Syarat:

- runtime optional;
- frontend lama tidak crash;
- no runtime project tetap mendapat response normal;
- error runtime enrichment tidak membuat seluruh workspace gagal, kecuali error security;
- tidak ada N+1 query berlebihan;
- query menggunakan index yang tersedia.

LANGKAH 9 — MANUAL VERIFICATION
==================================================

Verifikasi minimal tiga project:

A. Live runtime project
- memiliki creative_project_steps;
- worker runtime tampil;
- current task nyata;
- tidak ada confidence demo;
- label live benar.

==================================================
LANGKAH 10 — SECURITY VERIFICATION
==================================================

Wajib periksa:

- unauthorized token → ditolak;
- token valid tetapi project berbeda → ditolak;
- no cross-tenant step lookup;
- no worker leakage dari project lain;
- no provider raw response;
- no prompt/system instruction;
- no API key;
- no internal stack trace;
- no sensitive cost metadata pada customer response.

Jika menemukan IDOR atau leakage, perbaiki sebelum fase dinyatakan selesai.

==================================================
LANGKAH 11 — PERFORMANCE
==================================================

Periksa:

- query count;
- N+1 metadata lookup;
- repeated agent/employee lookups;
- unnecessary frontend rerender;
- runtime adapter called more than once per request;
- large response;
- missing index.

Gunakan batched lookup untuk metadata enrichment.

Jangan menambahkan cache kompleks pada fase ini kecuali benar-benar diperlukan.

PHASE 3 — CREATIVE AI BRIEF INTELLIGENCE ENGINE
OBJECTIVE

Phase 1, Phase 2, Phase 2.1, dan Phase 2.2 telah selesai.

Sekarang bangun Brief Intelligence Engine sebagai otak rekomendasi untuk seluruh layanan Creative AI.

Tujuan utama fase ini:

Ketika user memilih industri, tujuan project, target audiens, layanan, dan konteks bisnis, sistem dapat menghasilkan rekomendasi brief yang relevan, konsisten, dapat dijelaskan, dan dapat diterapkan ke form hanya setelah mendapat persetujuan user.

Fase ini bukan AI chatbot.

Fase ini bukan website scraping.

Fase ini bukan generative AI call.

Bangun dahulu recommendation engine yang deterministic, testable, reusable, dan tidak bergantung pada model AI eksternal.

Contoh pengalaman yang dituju:

User memilih:
Coffee Shop

Engine merekomendasikan:
- Brand personality: Hangat, Ramah, Premium
- Style: Modern, Minimalis, Natural
- Color: Cokelat, Cream, Dark Green
- Audience: Anak muda, Profesional, Konsumen umum
- Deliverables: Logo, Brand Guideline, Packaging, Social Media Kit
- Photography: Natural lighting, Lifestyle, Product close-up

User kemudian dapat memilih:

Gunakan Semua Rekomendasi

atau menerapkan rekomendasi satu per satu.

PRINSIP ARSITEKTUR

Brief Intelligence Engine harus:

deterministic;
berbasis rule dan configuration;
dapat diuji tanpa API eksternal;
tidak mengubah pilihan user secara otomatis;
tidak overwrite jawaban user tanpa konfirmasi;
reusable untuk semua layanan Creative AI;
dapat dikembangkan bertahap;
tidak hardcode logic besar di halaman React;
tidak bergantung pada bahasa label UI;
menggunakan stable keys;
memiliki confidence dan reason;
mendukung fallback;
tidak mengubah backend contract existing.
BATASAN WAJIB

Jangan mengubah:

database schema;

production pipeline;

15. SCORING ENGINE

Buat scoring deterministic.

Contoh konsep:

Industry profile match       +40
Service profile relevance    +30
Goal relevance               +20
Audience relevance           +15
Company size relevance       +5
Priority relevance           +5
Existing user selection      special handling
Conflict penalty             -30

Nilai hanya contoh. Tentukan bobot yang masuk akal dan dokumentasikan.

Engine harus:

menggabungkan duplicate recommendation;
mengakumulasi reasons;
mengakumulasi sources;
melakukan deduplication berdasarkan stable key;
menormalisasi score;
menentukan confidence;
memotong hasil sesuai limit;
menghasilkan urutan stabil;
menghasilkan output sama untuk input sama.

Tambahkan deterministic tie-breaker berdasarkan registry order atau key.

17. CONFLICT DETECTION

Buat conflict detection ringan.

Contoh kemungkinan konflik:

Luxury + Playful
Government + Highly Playful
Corporate B2B + Childlike
Premium Market + Extremely Colorful

No Assets + recommendation yang membutuhkan banyak existing photography

Jangan membuat rule terlalu kaku.

Output conflict harus berupa warning, bukan blocking error.

Contoh:

{
  code: "STYLE_AUDIENCE_MISMATCH",
  severity: "info",
  message: "Gaya Playful mungkin kurang sesuai untuk target Government.",
  affectedKeys: ["playful", "government"]
}

result dapat di-memo berdasarkan normalized context.

Jangan melakukan optimasi prematur yang membuat kode sulit dibaca.

36. ACCESSIBILITY

Panel recommendation harus:

keyboard accessible;
tombol memiliki label jelas;
card bukan satu-satunya clickable area tanpa role;
reason dapat dibaca screen reader;
status apply diumumkan menggunakan live region;
warning tidak hanya mengandalkan warna;
focus kembali ke posisi relevan setelah modal konfirmasi.
37. SECURITY DAN PRIVACY

Karena engine lokal:

jangan kirim brief ke provider AI;
jangan log seluruh brief di production;
jangan masukkan token/request ID ke debug panel;
jangan simpan recommendation ke localStorage terpisah;
recommendation dapat dihitung ulang dari brief;
jangan expose internal admin data.
38. JANGAN MENGUBAH LABEL MENJADI DATA ENGINE

Pastikan translation/UI copy terpisah dari stable key.

Contoh:

key: "corporate"
labelId: "Corporate"
labelEn: "Corporate"

Jangan menyimpan key ke backend jika backend sebelumnya menyimpan label string, kecuali sudah ada adapter yang memastikan payload existing tetap sama.

Frontend engine boleh memakai key.

Serializer akhir tetap mengikuti kontrak brief existing.

39. ACCEPTANCE CRITERIA

Phase 3 selesai hanya jika:

Engine deterministic dan tidak memakai AI API.
Industry profile registry tersedia.
Service profile registry tersedia.
Goal dan audience rules tersedia.
Recommendation memiliki score, confidence, source, dan reason.
Duplicate recommendation digabung.
Conflict menghasilkan warning non-blocking.
User selection tidak pernah ditimpa otomatis.
Gunakan bekerja.
Gunakan kategori ini bekerja.
Gunakan semua rekomendasi hanya mengisi field kosong.
Autosave hanya berjalan setelah apply.
Recommendation calculation tidak autosave.
Unknown industry memakai fallback aman.
Engine tidak crash untuk unknown service.
Brief payload backend tetap sama.
Legacy parsing tetap berjalan.
Review menampilkan hasil applied.
Refresh memulihkan applied values.
Unit tests lolos.
Typecheck lolos.
Build lolos.
Visual verification dilakukan.
Tidak ada perubahan database/API/pricing/workflow.

REQUEST CONTRACT
==================================================

Request minimal:

- tenant context;
- projectId;
- workflowId;
- stageId;
- capabilityId;
- pluginId;
- input artifacts;
- structured brief context;
- structured parameters;
- requested output types;
- idempotencyKey;
- budget policy;
- quality policy;
- correlationId;
- actor context.

Jangan menerima raw provider API key.

Jangan menerima provider/model sebagai authoritative request dari customer.

Provider preference hanya boleh dipertimbangkan jika policy existing mengizinkan.

==================================================
CAPABILITY RESOLUTION
==================================================

Resolver harus:

- mencari capability canonical;
- memvalidasi plugin ownership;
- memvalidasi contract version;
- memvalidasi input artifact;
- memvalidasi output artifact;
- memvalidasi guardrail;
- memvalidasi tenant;
- memvalidasi budget;
- menentukan execution mode;
- menghasilkan explicit failure.

Jangan silent fallback ke capability yang berbeda.

==================================================
EXECUTION PLAN
==================================================

Plan dapat mencakup:

- single agent;
- sequential agents;
- parallel independent tasks;
- validation step;
- transformation step;
- QC step;
- human review requirement.

Team 31 tidak boleh membuat workflow engine kedua.

Execution plan harus berasal dari workflow/capability definition existing.

==================================================
OUTPUT
==================================================

Output harus:

- structured;
- versioned;
- mempunyai provenance;
- mempunyai model/provider metadata yang aman;
- mempunyai cost record reference;
- mempunyai job ID;
- mempunyai artifact descriptors;
- mempunyai validation status;
- mempunyai warning;
- tidak mengandung secret;
- tidak menyimpan raw chain-of-thought.

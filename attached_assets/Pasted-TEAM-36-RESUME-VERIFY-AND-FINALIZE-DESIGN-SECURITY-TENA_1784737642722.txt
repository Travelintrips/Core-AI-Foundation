PHASE 4 — POLICY CONTRACT VALIDATION
==================================================

Pastikan contract minimal tersedia dan tidak membuat RBAC vocabulary tandingan:

DesignSecurityPolicy
DesignResourceScope
DesignPermission
DesignSecurityDecision
DesignSecurityReason
DesignPolicyEvaluator
DesignSecurityAuditEvent
DesignRateLimitPolicy
DesignResourceLimitPolicy

Requirements:

- structured output;
- deterministic decision;
- explicit allow/deny;
- machine-readable reason;
- tenant scope;
- platform scope;
- actor context;
- resource context;
- no client-authoritative tenant ID;
- no second RequestContext model.

Jika RBAC existing mempunyai permission names canonical, gunakan mapping/adapter,
bukan enum baru yang bertentangan.

==================================================
PHASE 5 — TENANT ISOLATION AND IDOR
==================================================

Verifikasi seluruh design-related route/service yang disentuh.

Required behavior:

- tenantId berasal dari RequestContext;
- body/query tenantId tidak menjadi authority;
- resource lookup tenant-scoped;
- update/delete tenant-scoped;
- missing tenant fail-closed;
- public token tidak menjadi tenant authority;
- platform access explicit;
- tenant actor tidak dapat memakai platform scope.

Audit kemungkinan IDOR pada:

- project;
- artifact;
- asset;
- material;
- component;
- annotation;
- review;
- export;
- cost;
- AI execution;
- rendering.

Jangan memperluas scope ke seluruh repository kecuali reusable security utility
memang dipakai bersama.

==================================================
PHASE 6 — PLUGIN SECURITY
==================================================

Pastikan plugin guard menolak:

- remote JavaScript;
- URL-based module;
- arbitrary import path;
- path traversal;
- arbitrary SQL;
- arbitrary executable code;
- unknown plugin ID;
- incompatible contract version;
- capability escalation;
- raw secret in manifest;
- untrusted renderer module;
- duplicate registry takeover.

Plugin harus:

- static/compiled;
- manifest validated;
- registry known;
- version checked;
- capability limited;
- permission-aware.

Tambahkan tests untuk positive dan negative cases.

==================================================
PHASE 7 — AI SECURITY
==================================================

Pastikan:

- provider keys berasal dari secret service;
- frontend/plugin tidak memanggil provider langsung;
- artifact metadata tidak dapat mengganti system instruction;
- structured input validation;
- structured output validation;
- no raw chain-of-thought persistence;
- no raw provider secret;
- no unrestricted tool execution;
- budget guard;
- resource guard;
- timeout/retry guard;
- prompt context delimiting/sanitization;
- actor/tenant context preserved.

Jangan membuat AI runtime kedua.

==================================================
PHASE 8 — SVG, HTML, AND MEDIA SAFETY
==================================================

Verifikasi implementasi SVG:

- raw SVG tidak di-inject ke DOM;
- script/event handler ditolak;
- external references ditolak bila unsafe;
- data URL policy explicit;
- safe image rendering;
- unsupported SVG state jujur;
- object URLs direvoke;
- HTML comments/metadata disanitasi;
- no dangerouslySetInnerHTML untuk untrusted content.

Tambahkan regression test untuk:

- script tag;
- onload/onerror;
- foreignObject;
- javascript URL;
- external href;
- safe raster image;
- unsupported SVG behavior.

==================================================
PHASE 9 — RATE LIMITING AND RESOURCE LIMITS
==================================================

Rate limit harus menggunakan existing limiter pattern.

Verifikasi minimal:

- public review token endpoint;
- expensive design execution endpoint;
- export/render request;
- upload boundary bila disentuh.

Resource limits minimal:

- maximum upload size;
- supported MIME;
- maximum request payload;
- maximum number of artifacts/assets;
- maximum execution concurrency boundary;
- maximum render dimensions;
- maximum comment/metadata length.

Requirements:

- structured error;
- no silent truncation;
- tenant/user-aware key;
- public token-aware key;
- cleanup;
- testable configuration;
- no unlimited default on config failure.

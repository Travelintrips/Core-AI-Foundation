==================================================
PHASE 2 — VERIFY DEF-001 IMPLEMENTATION
==================================================

Periksa implementasi deduplication yang telah dibuat.

Jangan menerima solusi yang hanya menggunakan in-memory Map sebagai proteksi utama jika aplikasi dapat memiliki:

- multiple workers;
- multiple server instances;
- restart;
- horizontal scaling;
- concurrent database transactions.

In-memory Map boleh digunakan sebagai optimization lokal,
tetapi bukan satu-satunya concurrency guarantee.

Server-side protection harus memiliki persistent or transactional guarantee.

Pilihan yang disarankan:

- idempotency key table dengan unique constraint;
- request/client ID unique tenant-scoped;
- project request fingerprint stored transactionally;
- existing canonical idempotency infrastructure.

Persyaratan:

- tenant-scoped;
- actor/customer-scoped;
- payload-aware;
- concurrency-safe;
- retry-safe;
- transaction-safe;
- tidak menggabungkan dua request berbeda;
- tidak membuat duplicate workflow;
- tidak membuat duplicate job;
- tidak membuat duplicate payment schedule;
- tidak membuat duplicate audit event.

Jika perubahan sebelumnya hanya berupa in-memory dedup map:

jangan langsung menghapusnya,
tetapi tambahkan database-backed guarantee atau gunakan infrastruktur idempotency existing.

Pastikan duplicate retry mengembalikan project canonical yang sama.

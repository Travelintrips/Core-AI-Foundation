# Developer Build Flow

Single source of truth → generated code → apps. This pipeline is designed so
no developer ever needs to hand-fix duplicate exports, duplicate schemas,
stale `dist/`, stale generated files, or manual wrapper code again.

```
lib/api-spec/openapi.yaml   (source of truth)
        │  pnpm run build:generated
        ▼
lib/api-client-react/src/generated/   (React Query hooks + response schemas)
lib/api-zod/src/generated/            (Zod request/response validators)
        │
        ▼
Frontend (artifacts/ai-platform)  ◄──uses──  lib/api-client-react
Backend  (artifacts/api-server)   ◄──uses──  lib/api-zod
```

## Source of truth

`lib/api-spec/openapi.yaml` is the **only** place API contracts are defined.
Never hand-write types, Zod schemas, or React Query hooks that duplicate what
codegen produces — if a shape is missing, add/fix it in the spec and
regenerate.

## Codegen

```bash
pnpm --filter @workspace/api-spec run codegen
# or from the repo root:
pnpm run build:generated
```

This runs `lib/api-spec/generate.mjs`, which calls Orval's programmatic API
directly (not the CLI) because Orval's bundled `@scalar/json-magic` file
loader cannot resolve local YAML files reliably in this pnpm workspace. The
script pre-parses `openapi.yaml` with the `yaml` package and passes the
parsed object straight to `orval.generate()`, skipping file resolution
entirely.

Two outputs, one spec:
- `lib/api-client-react/src/generated/` — `client: "react-query"`, mode `split`
- `lib/api-zod/src/generated/` — `client: "zod"`, mode `split`

`api-zod` intentionally does **not** enable Orval's separate TypeScript
`schemas` output — that produced a second, unused copy of every type under
`generated/types/`, which duplicated the Zod schema exports. `api-zod` only
ever exports Zod schemas, inferred types (via `z.infer<>`), and hand-written
helpers/validators — never generated TS interfaces that could collide with
schema names.

## Build order

```bash
pnpm run build:generated   # 1. openapi.yaml → generated/ (both packages)
pnpm run build:libs        # 2. tsc --build (project references, type-only)
pnpm run build:api         # 3. esbuild bundle of artifacts/api-server
pnpm run build:workspace   # runs 1 → 2 → 3, then builds the frontend
```

Each step depends on the previous — never run `build:api` without a fresh
`build:generated` first if the spec changed.

## Verification

```bash
pnpm run verify:openapi    # openapi.yaml parses cleanly, no duplicate operationIds
pnpm run verify:generated  # generated/ dirs exist, have Orval headers (untampered),
                            # no duplicate exports, dist/ isn't stale
pnpm run verify:types      # full workspace typecheck
pnpm run verify            # all of the above
```

The checker lives at `scripts/src/workspace-check.ts`
(`pnpm --filter @workspace/scripts run workspace-check`). Run it with
`--health` to get a JSON report instead of a pass/fail exit code
(`pnpm run workspace-health`). The same data is exposed at runtime via
`GET /api/internal/workspace-health` (admin-key protected) on the API server.

## Cleaning & rebuilding

```bash
pnpm run clean:generated   # removes generated/ in both packages
pnpm run clean:workspace   # + removes all artifact dist/ output
pnpm run rebuild:all       # clean:workspace → build:workspace → verify
```

## Generated file protection

Every generated file starts with an Orval header comment
(`Generated by orval ... Do not edit manually.`). `verify:generated` fails
the build if any generated file is missing that header — the signal that a
developer hand-edited a generated file instead of changing the OpenAPI spec.
If you need different output, change `openapi.yaml` or
`lib/api-spec/generate.mjs`'s Orval `override` options, then regenerate.

## CI

```bash
pnpm run ci:codegen   # regenerate from spec
pnpm run ci:verify    # verify:openapi + verify:types
pnpm run ci:build     # full workspace build
pnpm run ci:test      # runs `test` in every package that defines one
```

All scripts are idempotent — safe to run repeatedly, including back-to-back
in the same CI job, without manual cleanup between runs.

## Debugging

- **"No matching export" errors in api-server**: `api-zod`'s generated
  schemas are stale relative to the route code. Run `pnpm run build:generated`
  then restart the API server workflow.
- **Duplicate YAML key / parse errors in openapi.yaml**: almost always a
  concatenation artifact from an import or merge (two versions of the same
  path/schema pasted back to back). `pnpm run verify:openapi` will show the
  exact line; keep the more complete (usually later) definition and delete
  the other.
- **`verify:generated` reports "manually edited"**: someone edited a file
  under `generated/` directly. Revert that file and make the equivalent
  change in `openapi.yaml` instead, then regenerate.

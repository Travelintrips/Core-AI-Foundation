# Phase 4 Design ZIP Export — Runtime Notes

## Key rules

**Idempotency contract (`enqueueZipExport`):**
- Returns `{ export: DesignRenderZipExport, created: boolean }`.
- Route MUST only call `enqueue()` when `created === true`. Calling enqueue on every POST duplicates jobs.
- Existing queued/generating export → `created: false`, no new job.
- Completed export with same fingerprint → `created: false`, return 200 (not 202).

**Why:** The first integration run created 2 jobs for the same export because the route re-enqueued on every POST while export was still `queued`.

**Zero-item guard (`EmptyBatchError`):**
- Thrown by `enqueueZipExport` when the batch has no completed items with an output path.
- Route catches it and returns `422 { error: "...", code: "EMPTY_BATCH" }`.
- Never produce a ZIP containing only `manifest.json`/`failures.csv` with zero content files.

**Download endpoint auth:**
- `GET /ai/design-zip-exports/:id/download` is in `PUBLIC_ROUTE_RULES` (not PUBLIC_PATH_PREFIXES).
- The signed HMAC token (generated by `generateZipDownloadToken`) is the sole credential.
- Token payload: `{ eid, tid, exp, nonce }`. Validates: signature, expiry, exportId match (URL param vs eid).
- Storage path (`zipStoragePath`) is never returned in any API response — only the binary stream.

**How to apply:** Any new download-like endpoint using its own signed token (not admin key) should be added to PUBLIC_ROUTE_RULES with an anchored regex, not PUBLIC_PATH_PREFIXES.

## Dev DB schema drift (phase4 integration)

The integration branch had two schema/DB drift issues that required hand-written DDL:

1. `design_render_zip_exports` — new table, applied via `20260716_design_render_zip_exports.sql`
2. `design_render_batches.cancelled_items` — column in Drizzle schema but missing from dev DB.
   Fixed with: `ALTER TABLE design_render_batches ADD COLUMN IF NOT EXISTS cancelled_items INTEGER NOT NULL DEFAULT 0;`

**Why:** Drizzle schema had `cancelledItems` (added in integration branch) but the dev DB table predated it. Always run `pnpm run build:generated` and check for "column does not exist" errors after an integration merge; these are schema drift indicators.

## Worker registration

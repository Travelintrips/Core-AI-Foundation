# Event-driven external-agent jobs

All external-agent jobs submitted through `submitCodingBridgeCommand` now emit a PostgreSQL NOTIFY wake-up after durable insertion. One session-mode LISTEN connection per API process forwards the hint to authenticated `/api/ai/agent-runtime/work/stream?clientId=...` SSE subscriptions. Hints contain only client/command IDs, never credentials or executable instructions. Existing agent:work scope, registry checks, atomic claims, lease fencing and result verification remain authoritative.

The shared VPS consumer, Python PC consumer, and JavaScript PC2 consumer use events instead of idle job polling. Every `ready` event drains the worker's durable backlog; subsequent `work_available` events drain newly queued work. Keepalive comments do not cause claim calls. Connections renew after five minutes to reauthenticate and reconcile missed hints. EOF, network timeouts and listener loss reconnect with bounded exponential delay. There is no automatic fallback to five-second queue polling.

LISTEN requires a persistent session. For the existing Supabase pooler URL on port 6543, only the listener derives port 5432 with the same database identity and credentials. Normal queries and notification publishing keep the existing database pool. No schema, roles, grants, replication publications or firewall changes are installed. Direct/custom URLs are left unchanged. An unavailable event listener returns 503 rather than falsely reporting event delivery.

NOTIFY is an advisory wake-up, not the durable queue. A process crash after insertion but before notification can delay work until reconnect reconciliation. The backend may deliver duplicate hints; they never themselves execute work. Long-running and interrupted side effects still require normal claim fencing/reconciliation. Result persistence is not proof of ChatGPT conversation delivery or reverse ACK.

Rollout order: deploy and verify the backend endpoint first; then replace a consumer only after checking it has no active work. Roll out separately to DEV and approved production environments. Windows consumer launchers must keep using their existing protected credential files; install `work-event-stream.mjs` beside the JS consumer. Do not overwrite a locally extended PC consumer without reviewing its differences. Inactive PC3/Android or unrelated queue systems are not activated by this change.

Acceptance: authenticate stream; prove idle keepalives cause zero additional claims; enqueue one read-only job and match command/response IDs; reconnect and drain an offline backlog; verify no duplicate execution and no pending result. Record actual worker, environment and source SHA. A browser/session ACK needs independent evidence and is not implied by these checks.
